# 가족 우편함 개발 계획서

여행 스케치의 부가 기능. 여행을 기록한 사람(보내는 사람)이 부모님 등(받는 사람)에게 **엽서**를 보내고,
받는 사람은 로그인 없이 링크로 보고 답장한다. (기획 확정: 2026-10-02 대화. 이 문서는 개발 계획이다.)

## 0. 확정된 기획 요약
| 항목 | 결정 |
|---|---|
| 위치 | 여행 스케치의 부가 기능. 같은 저장소, 받는 화면은 `/m/…` 로 따로 |
| 우편함 | 집 한 곳당 하나(부모님 두 분은 한 우편함). 보내는 사람은 여러 우편함에, 한 우편함에는 보내는 사람 여럿 |
| 인사말 | 우편함마다 따로. 복사 후 수정. **호칭은 본문과 따로 저장**, 보낼 때 맨 앞에만 붙임 |
| 사진 | 엽서당 **한 번만 복사**(960px), 우편함끼리 공유. 보낸 순간 그대로 남음 |
| 삭제 | 원본 사진을 지우면 복사본 삭제, **여행을 지우면 엽서 통째로 삭제**, 복사본을 못 지우면 원본도 못 지움 |
| 받는 쪽 | 로그인 없음(비밀 링크), 큰 글씨, 답장 단추, "엄마/아빠" 구분 |
| 한도 | 우편함 3개(첫 버전은 결제 없이 모두 같은 한도), **엽서 한 장에 사진 3장**. **우편함 하나에 쌓이는 엽서 수와 사진 총량은 첫 버전에서 한도 없음**(나중에 유료 구분: 무료는 최근 10장 보관, 가족 플랜은 전부) |
| 하지 않는 것(첫 버전) | 자동 발송(알림톡·문자), 음성 답장, 디지털 액자, 실물 엽서, 결제 |

## 2. 데이터 설계 (`supabase/mailbox.sql`, 사용자가 SQL Editor 에서 실행)
```
mailboxes            id, owner_id(만든 사람), name, greeting_name(부르는 말), tone('casual'|'polite'),
                     use_greeting_name(앞에 호칭 붙이기), token(길고 짐작할 수 없는 글자, 새로 만들 수 있음),
                     closed_at, created_at
mailbox_senders      mailbox_id, user_id, role('owner'|'sender'), created_at       -- 보내는 사람들
mailbox_invites      token, mailbox_id, expires_at, used_at, used_by                -- 보내는 사람 초대(7일·한 번)
postcards            id, sender_id, trip_id(on delete 지정 아래), title, body, map(좌표 흐림, 곳 이름),
                     photos jsonb(파일 이름과 원본 사진 id 목록), created_at
postcard_deliveries  postcard_id, mailbox_id, greeting(우편함별 본문 앞 인사말), delivered_at
postcard_replies     id, postcard_id, mailbox_id, who('엄마' 등), reaction, created_at, seen_at
postcard_ids         쓴 id 기록(링크 공유의 sketch_share_ids 와 같은 까닭: 지운 주소 재사용 금지)
```
- 공개 보관함 `postcards`(새 버킷, 공개). 엽서마다 폴더 하나: `postcards/<postcardId>/<파일>`.
- **받는 쪽은 표를 읽지 않는다.** RPC 만 연다: `mailbox_view(token)`, `mailbox_postcard(token, postcard_id)`,
  `mailbox_reply(token, postcard_id, who, reaction)` (전부 `security definer`, 이 토큰의 우편함 것만 돌려줌).
- 보내는 사람은 RLS 로 자기 우편함·엽서만. `family_can` 은 쓰지 않는다(우편함은 가족 공유와 별개).
- 한도(우편함 3개)는 DB 트리거로도 막는다(`family_links_limit` 과 같은 방식).
- 가족(추가도 가능)이 여행을 지울 때를 막으려 `postcards_select_family`(full) 를 더한다(링크 공유와 같은 이유).

## 3. 단계별 계획
크기: S(반나절) / M(하루) / L(이틀+). 모든 단계는 **테스트 먼저**(TDD), 끝나면 배포 후 폰 확인.
앞 단계가 끝나기 전에 뒤 단계를 배포하지 않는다. **3단계(보내기)와 4단계(삭제 규칙)는 함께 배포한다** —
삭제 규칙 없이 보내기만 열면 복사본이 남는 구멍이 생긴다.

### 1단계 · 데이터와 규칙 (M)
- `supabase/mailbox.sql`: 위 표, RLS, RPC 셋, 한도 트리거, 키 고정 트리거(주인·토큰 칸), `postcards` 정책.
- `lib/mailbox.ts`(순수): 한도 상수, 토큰 만들기·검사, 호칭+본문 합치기(`composeGreeting`), 인사말 복사
  (`copyGreeting`: 본문은 그대로, 호칭만 우편함 것), 추천 문구, 엽서 사진 고르기 추천(`pickPostcardPhotos`).
- `lib/mailboxSql.test.ts`: family.sql 과 같은 방식으로 SQL 에 규칙이 적혀 있는지 시험.
- **사용자 할 일:** Supabase 에서 공개 버킷 `postcards` 만들기, `mailbox.sql` 실행.

### 2단계 · 우편함 만들기와 관리 (M)
- 화면 `/mailboxes`(내 우편함): 만들기(이름·부르는 말·말투), 목록(보내는 사람 수·마지막 엽서·답장·열어 본 여부),
  [링크 복사][링크 새로 만들기(옛 링크 끊기)][우편함 닫기].
- 보내는 사람 초대: `mailbox_invites` 수락 화면 `/mailboxes/join/[token]`(수락 버튼을 눌러야 연결 — 가족 공유와 같은 이유).
- `lib/supabase/mailbox.ts`(데이터), `components/mailbox/MailboxPanel.tsx`.
- 들어가는 길: 위 띠 이름 메뉴 또는 도움말. 여행 상세에도 [엽서 보내기] 단추는 3단계에서.

### 3단계 · 엽서 보내기 (L)
- 여행 상세의 [엽서 보내기] → 시트: 사진 3장(자동 추천, 바꿀 수 있음), 본문, 받을 우편함 체크.
- 인사말: 첫 우편함에 쓴 본문이 다른 우편함에 복사, **호칭만 바뀜**, 직접 고치면 그 우편함만 따로("직접 고쳤어요"),
  [원래대로]. 존댓말 우편함에는 추천 문구 칩.
- 사진 복사: 고른 3장을 `thumbUrls`로 받아 `postcards/<id>/…` 에 **한 번만** 올림. 우편함 수와 무관.
  올리다 실패한 사진은 엽서에서 빼고(링크 공유와 같은 규칙), 남은 것만 기록. 폴더 청소(`sweepFolder`).
- 지도·곳 이름은 보낸 순간 것을 베낌(위치는 약 1km 로 흐림, 메모·동행자 이름은 싣지 않음. 동행자는 보낸 사람이 켠 때만).
- 보내기: `navigator.share`(폰의 공유창 → 카카오톡 포함, 새 키 불필요). 안 되는 브라우저는 링크 복사.
  링크 미리보기(og:image)는 엽서 첫 사진으로.
- `components/mailbox/SendPostcard.tsx`, `lib/supabase/postcards.ts`.

### 4단계 · 삭제 규칙 (M) — 3단계와 함께 배포
- `deleteTrip`: 그 여행의 엽서가 있으면 **복사본 폴더를 먼저 비우고 → 엽서 기록 삭제 → 여행 삭제**. 비우지 못하면 여행도 지우지 않고 "다시 해 주세요".
- `deletePhoto`: 그 사진이 쓰인 엽서의 복사본만 지우고 엽서 안 빈 칸 표시.
- 엽서 거두기: 모든 우편함에서 삭제, 복사본 삭제.
- 확인 창: 보낸 엽서가 걸린 여행·사진을 지우려 할 때만 "엽서 N장도 함께 지워져요" 한 번 더.
- 가족(추가도 가능)이 지울 때는 엽서가 걸려 있으면 멈춤(`postcards_select_family`).
- 보관함 정리(`StorageSweep`)에 엽서 보관함의 안 쓰는 파일 찾기·지우기를 더함. 탈퇴 운영 메모에 `postcards` 폴더 삭제 추가.

### 5단계 · 받는 쪽 화면 (L)
- `/m/[token]`(우편함 첫 화면), `/m/[token]/p/[postcardId]`(엽서 한 장). 서버 렌더, 로그인 없음, `noindex`.
- 어르신 화면: 본문 18px 이상, 단추는 손가락 크기, 한 화면에 엽서 한 장, 메뉴·설정 없음.
- 엽서: 큰 사진(넘겨 보기), 이름·날짜·곳, 보낸 사람의 인사말, 지도와 발자취 재생(`FootprintPlayer` 재사용).
- 우편함 목록: 보낸 사람으로 거르기, 새 엽서 표시, 답장함 표시.
- "누가 보시나요?"(엄마/아빠 같은 이름): 처음 한 번 고르면 그 폰에 기억(`localStorage`). 이름 목록은 우편함 만들 때 부르는 말에서.
- 홈 화면에 추가: 우편함마다 `manifest`(`/m/[token]/manifest.webmanifest`)로 아이콘이 그 우편함을 바로 연다.
- 끊긴 링크·닫힌 우편함·지워진 엽서: 부드러운 안내("보낸 분이 지웠어요"). 코드·오류 문구 노출 금지.
- 받는 사람의 [더 받지 않기]: 우편함을 닫는 요청을 보낸 사람에게 알림.

### 6단계 · 답장과 알림 (M)
- 단추 셋(기본 문구 + 보낸 사람이 바꿀 수 있음)으로 답장, `mailbox_reply`.
- 보내는 사람 앱: 엽서별 답장 목록("엄마가 '좋구나' 하셨어요"), 안 읽은 점. 알림은 앱 안 표시까지(푸시는 이후).
- 한 엽서에 한 사람이 여러 번 답하는 것 허용, 마지막 것만 표시. 속도 제한(스팸 방지).

### 7단계 · 문구와 마감 (S)
- 도움말: "가족 우편함" 항목. 개인정보처리방침: 받는 사람 정보(부르는 말·답장), 복사본 보관·삭제, "받는 분이 저장한 것은 지울 수 없다", 이메일·주소 미수집.
  이용약관: 엽서 책임(보낸 사람). 시행일은 이미 있음 — **방침이 바뀌므로 알림 기간 안내 필요**.
- 전체 시험·빌드·배포, GitHub 푸시와 태그.

## 4. 시험 계획
- 순수 함수: 호칭 복사(`copyGreeting`)·인사말 합치기·사진 추천·토큰 — 단위 시험.
- SQL 글 시험: 모든 정책·한도·RPC 가 `security definer`, 받는 쪽이 표를 못 읽음, 키 고정 트리거.
- 삭제 규칙: 가짜 Supabase 로 "복사본 먼저, 기록 나중", "복사본 실패 시 여행 안 지움", 가족 권한 차단.
- 화면: 보내기 시트(복사·직접 고침 표시), 우편함 관리, 받는 쪽(권한 없는 링크·닫힌 우편함), 답장.
- 실사용: 계정 두 개(보내는 사람 A, 형제 B)와 폰 한 대(받는 쪽, 로그인 안 한 상태)로 한 바퀴 — 보내기→받기→답장→삭제.

## 5. 위험과 대책
| 위험 | 대책 |
|---|---|
| 비밀 링크가 퍼짐 | 길고 짐작할 수 없는 토큰, [링크 새로 만들기]로 옛 링크 즉시 끊기, 받는 사람 [더 받지 않기] |
| 복사본 고아 파일 | 지울 때 파일 먼저, 보관함 정리에 엽서 보관함 추가 |
| 용량 | 엽서 한 장 약 0.4MB(100장이면 약 40MB). 우편함 수와 무관(엽서당 한 번 복사). **우편함당 한도가 없으므로** 시험 기간에 `postcards` 버킷 크기와 우편함별 엽서 수를 확인한다(아래 SQL). 하루 한도처럼 급한 것은 아님 |
| 개인정보 | 위치 1km 흐림, 메모·동행자 미포함(동행자는 선택), 처리방침 갱신 |
| 어르신 사용성 | 글씨·단추 크게, 선택지 최소, 폰 실제 확인을 단계마다 |
| 받는 쪽 스팸·남용 | 답장 속도 제한, 우편함당 엽서 수·크기 한도 |
| 일이 커짐 | 3·4단계는 한 묶음, 나머지는 단계별 배포. 자동 발송·결제·음성은 이번 범위 밖 |

## 6. 첫 버전에서 일부러 뺀 것(이후)
- 우편함당 엽서·사진 총량 한도(무료는 최근 10장 보관, 가족 플랜은 전부 — 시험 결과를 보고 정함).
- 자동 발송(알림톡·문자)과 부모님 수신 동의, 음성 답장, 디지털 액자 모드, 실물 엽서 업셀, 결제와 가족 플랜 한도 차등,
  AI 말투 변환, 푸시 알림.

## 7. 시작하기 전에 확인할 것(사용자)
1. **10가족 시험을 먼저 할지** — 개발 없이 지금의 여행 링크 공유로 2주(권장, 개발 비용을 쓰기 전 검증).
2. Supabase 에서 공개 버킷 `postcards` 만들기(1단계 직전).
3. 한도 수치(우편함 3개, 사진 3장, 가족 보내는 사람 수)를 이대로 쓸지.
4. 이름: "가족 우편함"으로 갈지.

## 8. 용량 확인용 SQL (읽기만 — 시험 기간에 쓴다)
```sql
select count(*) as 엽서수, pg_size_pretty(sum((metadata->>'size')::bigint)) as 크기
from storage.objects where bucket_id = 'postcards';

select mailbox_id, count(*) as 엽서수 from postcard_deliveries group by 1 order by 2 desc limit 10;
```

## 9. 진행 상황 (2026-10-02 기준)
1~7단계 모두 배포됨. 계획과 달라진 점:
- 받는 쪽의 "열어 봤다" 표시는 읽는 함수(mailbox_postcard)가 아니라 화면이 연 뒤 따로 부르는 mailbox_open 이 적는다
  (카카오톡 미리보기 기계가 링크를 읽어 가도 "읽으셨어요"가 찍히지 않게).
- 우편함 지우기는 만들지 않았다(닫기만). 지우면 엽서 사진 복사본이 걸린 곳이 없어 남을 수 있어서다.
- 엽서 보관함(postcards)의 "줄 없이 남은 폴더"는 앱에서 찾을 수 없다 — 보관함 정책이 엽서 줄이 있는 폴더만 보여 주기
  때문이다. 줄 없는 폴더는 supabase/mailbox.sql 끝의 검색(SQL Editor)으로 찾고, 대시보드 Storage 에서 지운다.
  회원 탈퇴 때도 같은 검색으로 그 사람의 엽서 폴더를 치운다.
- 보내기 단추는 흐리게 막지 않고, 눌렀을 때 빠진 것(한 줄·이름·우편함)을 말로 알린다.

## 10. 우리 가족 책장 (2026-10-07 시작)
우편함을 "책장", 엽서를 "책 한 권(한 여행)"으로 키우는 확장. 음성 녹음은 하지 않는다. 설정은 모두 **권장값이 기본**.
- **0단계 설정 틀 · 완료** — `mailboxes.settings`(jsonb). 사진 수 6·12·20(권장 20), 사진 크기 640·960(권장 640), 부모님 글씨 크게,
  하트(사진마다), 답장 문구 3개(좋구나/잘 다녀왔니/다음엔 같이 가자), 보관 최근 10권, 작년 오늘, 올해의 책. 비어 있는 칸은 권장으로 읽는다.
  받는 쪽에는 font·heart·words·past·year 다섯 개만 내려간다(`mailbox_view`·`mailbox_postcard`).
- **1단계 앨범 확장 · 완료** — 한 권 사진 최대 20장(640px, 장당 약 0.05~0.07MB), 받는 쪽은 한 장씩 넘겨 보는 앨범(`PhotoAlbum`).
  여러 책장에 보낼 때는 가장 적은 사진 수·가장 선명한 크기에 맞춘다(`sendLimits`).
- **2단계 하트 · 완료** — `postcard_hearts`(엽서·우편함·이름·사진 파일, 파일이 빈 글자면 책 하트) 표와 `mailbox_heart(box_token, card_id, who, file, on)` 함수.
  누르면 켜지고 한 번 더 누르면 꺼진다(두 번 눌러도 탈이 없다). 설정 `heart`가 photo(권장)면 사진마다, book이면 책 하나에 한 번 — 서버가 설정과
  다른 쪽은 거절한다("하트 방식이 바뀌었어요"). 한 엽서·우편함에 한 시간 60번·모두 200개까지. 받는 쪽은 `mailbox_postcard`의 `hearts`로 읽고,
  보낸 사람은 `postcard_hearts`를 읽어 "엄마가 사진 3장에 하트를 눌렀어요"와 위 띠 새 소식(사람 한 명이 스무 장에 눌러도 소식 하나)으로 본다.
  하트 설정이 설정 화면에 나온다(사진마다/책마다).
- **3단계 책장 홈 · 완료** — 부모님 첫 화면: 새로 온 엽서(안 열어 본 것, 큰 카드) → 작년 오늘 → 책꽂이(열어 본 책을 해마다, 표지 2열 격자,
  가장 새 해만 펼침). 해마다 '○○년 다녀온 곳 지도로 보기'(발자취 재생을 링크로 받은 모양으로 재사용, 단추를 눌러야 불러옴).
  작년 오늘 = 오늘 앞뒤 3일 안에 다녀온(여행 기간에 오늘이 걸쳐도 포함) 지난 해의 책 중 가장 가까운 한 권. `mailbox_view` 에 책마다
  `endedOn`·`places`(곳 이름·흐린 좌표·날·사진 수·첫 사진)를 더했고, 스냅샷 통째는 내리지 않는다. 설정 화면에 '작년 오늘'(권장 켬).
- 4단계 올해의 책 / 5단계 이름 바꾸기·보관 권수 줄이기 / 6단계 가고 싶은 곳 보내기.
- 설정 항목 중 보관·작년 오늘·올해의 책은 값만 저장되고, 해당 기능이 들어오기 전까지 화면에는 나오지 않는다.
