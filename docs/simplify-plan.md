# 줄이기 안 (2026-10-14)

일반 사용자에게 앱이 복잡해 보인다는 걱정에서 시작했다. 기능을 네 칸으로 나눈 초안이다. 결정은 ① 이 표, ② 기능별 쓰인 횟수(lib/usage), ③ 처음 쓰는 가족의 관찰을 맞춰 보고 사용자가 한다.

## 왜 복잡한가

- 한 앱에 서비스가 셋이다 — 내 여행 기록 / 여행 100선(관광 안내·코스·지역) / 가족 책장(엽서). 로그인 전 첫 화면은 여행 100선이다.
- 앱이 해야 할 정비가 버튼으로 나와 있다 — 해외 장소 이름 새로 붙이기, 보관함 정리.
- 같은 것을 보는 길이 여럿이고 이름이 낯설다 — 내 여행 지도·목록·한장 요약·발자취·여행 상세 지도, 한장·책장·우편함·칠한 곳·발자취.
- 숫자: 화면 주소 약 27개, 도움말 59항목.

## 네 칸

| 칸 | 기능 |
|---|---|
| 앞에 둘 것 | 사진 고르기(여행 자동 묶기), 내 여행 지도, 한장 요약 저장·공유, 부모님께 엽서 |
| 필요할 때만 | 기간 막대, 100선 겹쳐 보기, 해외 보기(해외 사진 있을 때만), 여행 다듬기·곳 이름 고치기, 기존 여행에 사진 더하기, 한장 모양·한 줄·전체 탭, 책장 설정·형제와 보내기·미리보기, 가족 공유, 빠진 곳 추천 |
| 자동으로 | 해외 장소 이름 새로 붙이기, 보관함 정리(다시 줄이기·안 쓰는 파일 지우기). 이미 자동: 썸네일 보충, 로그인 뒤 이어 기록 |
| 뺄 후보 | 지도의 '칠한 곳'(한장 '밟은 시도'와 겹침), 코스 짜기, 지역 보기, 곳별 방문 화면, 가고 싶은 곳 받기, 발자취 재생 |

## 사용자가 정할 것

- 로그인 전 첫 화면을 여행 100선(관광 안내)으로 둘지, 내 여행 스케치 소개로 바꿀지.
- 하단 탭 5개(내 여행 · 한장 요약 · 사진 고르기 · 여행 100선 · 내 정보)를 그대로 둘지.
- 뺄 후보 각각 — 쓰인 횟수를 본 뒤.

## 횟수 세기

2026-10-14 부터 센다(lib/usage 의 USAGE_STARTS). 방침 1항 마지막 줄·4항에 "어떤 화면을 열고 어떤 기능을 썼는지"를 적었다(개발 단계라 따로 알리지 않음 — 사용자 결정). 보는 법은 supabase/log.sql 아래쪽.
